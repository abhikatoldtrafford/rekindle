# M3 — semantic understanding: design and implementation plan

**Status:** implemented. Measured results are in
[docs/audit-m3-semantic.md](../../audit-m3-semantic.md).

**Order of work, honestly.** This plan was not written before the audit. The
model choice depended on a benchmark that needed torch installed, and the
brief was explicit that discovering a broken model download at the end would
waste the milestone — so the sequence was: verify the machine → verify that
weights download → benchmark two models on real photos → write this plan →
implement → test → verify. The task list below is the one that was executed,
not a reconstruction.

---

## 1. What this milestone adds, and why

Three capabilities, one shared embedding space, plus a face detector that is
deliberately *not* built on that space.

| Capability | The problem it solves | Measured on the reference index |
|---|---|---|
| **Scene clustering** | Every recipe in the design selects on people, albums, GPS or time. A photo with none of those is invisible. | 8,433 live photos have no face tag; **7,037** of those also have no album that is not a `Photos from YYYY` Takeout bucket. |
| **Semantic search** | There is no text path into the library, in any form. | 0 of 19,480 photos are reachable by describing them. |
| **Aesthetic ranking** | Sharpness-and-exposure ranks a crisp wall above a soft photo of someone laughing. | Kashmir has 508 live images; a memory wants ~40. |
| **Face gate** (separate model) | The publish rule needs non-empty face tags ⊂ allow-list, which default-denies all 8,433 untagged photos, landscapes included. | 8,433 photos currently un-publishable on a technicality. |

## 2. The four settled decisions, and how they were honoured

**(1) A strong model on torch+CUDA, with an ONNX CPU fallback, chosen with
evidence.** Both candidates were downloaded and run over 540 real photos from
nine real albums. CLIP ViT-L/14 is the default. The full table is in the audit;
the decisive facts were that CLIP encodes 2.2× faster at half the VRAM, wins
k-means purity against album labels 0.741 vs 0.585, and is the **only**
candidate with both a public pre-built ONNX export and a public aesthetic head
trained on its embedding space. SigLIP SO400M wins 1-NN (0.980 vs 0.956) and
stays in the registry as a torch-only alternative.

**(2) The three CLIP capabilities.** Built, in the order the brief's scope
discipline gives.

**(3) The person gate uses a real face detector.** YOLOv11n-face (Apache-2.0)
by default, SCRFD-10G available and labelled non-commercial. No CLIP anywhere
near this decision.

**(4) No local VLM.** None added.

## 3. Architecture, and the constraint that shaped it

M2 is being built concurrently in the main worktree. It edits `db.py`,
`cli.py` and `pyproject.toml`, and it bumps `SCHEMA_VERSION`. The design
target was therefore: **make the merge boring.**

```
src/rekindle/semantic/
    availability.py   is the extra installed? what is missing? (no heavy imports)
    runtime.py        which device, and is that a surprise? (nvidia-smi cross-check)
    registry.py       pinned repos, revisions, licences. Metadata only.
    setup.py          the ONLY module allowed to touch the network
    model-locks.json  sha256 of every pinned file
    torchfile.py      read a .pth into numpy, without torch, with an allow-list
    encoder.py        ImageTextEncoder protocol; TorchEncoder, OnnxEncoder
    photos.py         READ-ONLY, version-agnostic view of the photo index
    store.py          embedding store: float32 matrix + its own manifest (stdlib only)
    vectors.py        bulk maths (the only module needing numpy)
    embed.py          the embed driver
    search.py         text -> photos
    cluster.py        spherical k-means + scene labels
    aesthetic.py      the LAION head + the spread rule
    faces.py          detector + gate + the review queue
    cli.py            every verb, attached by register(app)
```

### Three choices that exist specifically to make the merge boring

**Embeddings are not a column on `photos`.** They are a separate directory
with a separate SQLite manifest and a **separate version counter**
(`STORE_SCHEMA_VERSION`), so this milestone does not touch `db.py` at all and
never competes for `SCHEMA_VERSION = 3`. The performance argument (a 768-dim
float32 vector is 3 KB; 18,201 of them is 56 MB of BLOBs in a table
`iter_photos()` streams in full on every enrich) is real but secondary. The
binding argument is that two independent stores merge as two additions,
whereas two sets of columns plus two migrations racing for one version number
is a hand-resolved conflict on a schema migration.

**`cli.py` gains two lines.** An import and `register_semantic(app)`. Every
verb body lives in `rekindle/semantic/cli.py`.

**The index is read through a new read-only reader, not `PhotoStore`.** Three
reasons, and the first alone is sufficient: `PhotoStore.__init__` *writes* —
`executescript(_SCHEMA)`, an `INSERT OR IGNORE`, and a `commit()` — and
creates the file if absent. Pointing that at a library you only mean to look
at is how an index gets damaged. Second, it refuses any schema version but its
own, and the reference index is **already at v3** from M2's work while this
branch's `db.py` says v2 — `PhotoStore` cannot open it and this reader can.
Third, it keeps `db.py` untouched. The cost is that a column rename breaks
this module silently, so `_require_columns` checks the column set at open time
and names what is missing.

### Optional extras

Two, not one, because the split is real:

* `semantic` — numpy, onnxruntime, huggingface-hub, tokenizers (~120 MB). CPU.
* `semantic-gpu` — adds torch and transformers (~2.5 GB). CUDA.

Neither is in the default `uv sync`. `numpy` alone is in the **dev group**, so
CI actually *runs* the search / clustering / aesthetic tests instead of
skipping them — a skipped test is not a passing test, and those are the three
modules where the arithmetic can be silently wrong.

PyPI's Windows torch wheel is CPU-only, so `[tool.uv.sources]` maps `torch` to
PyTorch's `cu126` index on win32/linux. `explicit = true` means that index is
consulted only for packages mapped to it, so it cannot perturb any other
resolution.

## 4. Tasks, each with the tests that hold it

### T1 — Machine audit and download verification
Verify the GPU, the CUDA toolchain, which hosts resolve, and that the chosen
weights actually land. **Before anything is built on the assumption.**

*Tests:* none — this is measurement, recorded in the audit document. Its
output is what the rest of the plan is built on.

### T2 — `availability` + `runtime`: degrade cleanly, and never lie about the device
*Tests* (`test_semantic_availability.py`, `test_semantic_runtime.py`, 24):
probe imports nothing; `require` names the missing modules *and* the install
command; CUDA chosen when torch sees it; **a CPU fallback on a machine with an
NVIDIA GPU produces a warning naming the GPU**; `--device cuda` raises rather
than falling back; `nvidia-smi` absent / garbage / timing out / exiting
non-zero are all survived.

### T3 — `store`: the embedding store
Stdlib-only: a float32 matrix plus a SQLite manifest.

*Tests* (`test_semantic_store.py`, 16): round-trip preserves values; rows are
dense and ordered; a rewritten hash **reuses its row** rather than growing the
matrix; the bytes on disk are literally little-endian float32
(`struct.pack("<4f", ...)`), which is the promise `numpy.frombuffer` relies
on; reopening at a different dim / model / revision is refused; a crash
between the matrix write and the manifest commit leaves an orphan tail that
the next open truncates; a truncated matrix is refused rather than guessed at.

### T4 — `photos`: the read-only index reader
*Tests* (`test_semantic_photos.py`, 18): a missing index names the command to
run; a non-database, a database with no `photos`, and a `photos` missing
columns each get their own message; **the reader does not write to the index**
(compared byte for byte, because Windows mtime granularity can hide a small
write); **a schema version it has never heard of is accepted**; archived,
trashed and video are excluded by default; `without_people` needs *both*
person fields empty; `real_albums` drops the year bucket; `existing_path`
skips a deleted copy.

### T5 — `encoder`: the protocol and two implementations
*Tests* (`test_semantic_onnx_preprocess.py`, 14): the preprocessing arithmetic
pinned against **hand-computed** values rather than snapshots of its own
output; aspect ratio preserved then centre-cropped; the ONNX embedding output
selected **by shape, not by position**; the transformers 4.x/5.x return-type
difference handled both ways.

### T6 — `embed`: the driver
*Tests* (`test_semantic_embed.py`, 15): the stored vector is *the encoder's
answer for that photo*, not merely "a vector was stored"; a second run embeds
nothing; a partial run resumes; a missing file and an undecodable file are
each **counted, not dropped**, and the accounting identity is asserted; a
whole bad batch does not stall the run; archived photos are not embedded;
batch size does not change the answer; `draft()` does not change the vector.

### T7 — `search`
*Tests* (`test_semantic_search.py`, 16): a query returns the matching colour;
**a different query returns different photos** (guards "returns the first k
rows regardless"); results ordered best first; `min_score` drops weak hits; an
album filter scopes the search and over-fetches so it still returns k; matrix
rows line up with their hashes.

### T8 — `cluster`
*Tests* (`test_semantic_cluster.py`, 16): three colours land in exactly three
pure clusters; **the same seed gives the same partition** (a user writes down
a cluster id); every seed still gives a correct partition; largest first;
`min_cosine` holds back what matches nothing; labels have a right answer and
a weak label is suppressed.

### T9 — `aesthetic`
*Tests* (`test_semantic_aesthetic.py`, 20): the score is the arithmetic it
claims; input renormalised; a multi-layer chain composes; **layers ordered
numerically, not lexically** (`layers.10` after `layers.2`); a mismatched
embedding space is refused rather than broadcast; the `.pth` reader refuses a
dangerous global (`os.system` via `__reduce__`) and a legacy format;
near-duplicate suppression works and backfills rather than returning short.

### T10 — `faces`: the gate
*Tests* (`test_semantic_faces.py`, 26): the rule is exhaustively tested
without a model — no detections is eligible; a weak detection is **uncertain,
not eligible**; exactly at the gate threshold is not eligible; the strongest
detection decides; the two thresholds must stay an order apart; the review
queue includes the eligible ones; the accounting identity is *capable of
failing*; precision/recall counts a miss as a false negative.

### T11 — `setup`: offline, pinned, checksummed
*Tests* (in `test_semantic_imports.py`, `test_semantic_cli.py`): every
revision is a full 40-hex commit; a branch name is rejected at construction;
every model records a licence with a URL; **a non-permissive model is never a
default** and must carry an explanatory note.

### T12 — CLI
*Tests* (`test_semantic_cli.py`, 16): every verb reachable; `doctor` and
`licences` run with no extras at all; every other verb refuses with a
*message* and exit code 3, never a traceback; and **one test goes all the way
through** with the toy encoder, because a file of tests that only ever assert
refusals would pass over a `find` that returns nothing.

### T13 — Import weight
*Tests* (`test_semantic_imports.py`): eight modules checked in a **clean
subprocess** — by the time the suite runs, pytest has already imported numpy
and an in-process check would pass regardless. Plus `test_the_check_can_fail`,
which imports numpy and asserts the check notices.

### T14 — Mutation testing
Break each line a test protects, watch the suite fail, restore. Results in the
audit document.

### T15 — Verification against the real library
Embed, cluster, search and gate 18,201 real images. Numbers in the audit.

## 5. What was deliberately not built

* **An ANN index.** 18,201 × 768 float32 is 56 MB and a query is one
  matrix-vector product. The design spec already carries an explicit
  escalation gate for vector search; brute force is correct until it trips.
* **DBSCAN / HDBSCAN.** Density clustering is the better fit — it can say
  "this photo is in no scene" — and it is another dependency with two
  parameters to tune per library. `min_cosine` is a poor substitute and is
  documented as one.
* **scikit-learn.** 30 MB for an algorithm shorter than its own configuration,
  whose k-means++ seeding determinism across versions is not promised.
* **Writing cluster ids back into the index.** That is a schema change, and
  the whole point of the storage design was not to make one while M2 is
  making one.
* **A local VLM.** Out of scope by decision 4.
